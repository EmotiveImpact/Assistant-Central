# Agent coordination

For new implementation work, open a draft pull request immediately, before
substantial code changes. A first commit containing a short work notice is enough
to make the draft concrete. Do not wait until implementation is complete to make
the work visible to other agents.

The initial PR description must identify:

- The coordinating agent and any assigned agents.
- The exact goal, base branch/PR and boundaries of the work.
- Claimed files or components, so other agents can avoid overlapping edits.
- Planned verification and any known dependencies or blockers.
- Whether the first commit contains coordination only or working implementation.

Keep the description current as assignments, scope and evidence change. Coordinate
overlapping edits with the current owner. Before starting, inspect relevant open
PRs for existing ownership and dependencies. Record changes in the PR, not only
in a private chat. Do not claim tests or behaviour that have not been verified.

Use separate work branches. Keep synthetic decisions distinct from authenticated
human consent and keep live provider activation explicit. Do not merge without
Augustus's explicit approval. Use British English in documentation.
