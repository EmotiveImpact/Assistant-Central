# Authenticated local owner draft review

This milestone adds an optional, default-disabled owner queue and explicit local
dismissal. It does not notify an owner, approve a task, stage or deliver a
proposal, execute a tool, enumerate conversation history or connect an existing
personal assistant account. The MCP surface still has exactly two tools.

## Trusted composition and credentials

`workspace_ui.host_draft_service.HostDraftService` wraps the existing owner
service. It authenticates the current owner and requires a configured public
identity fingerprint. That full fingerprint must also be the bridge binding's
`ownerId`; arbitrary model-selected owner labels cannot be mapped into authority.
The browser submits only a configured connection ID, draft ID, exact digest and
opaque review token. The host retains responsibility for provisioning the MCP
binding only after authenticating the real owner.

The private configuration has version `assistant-central-host-draft-review/1`
and up to eight `connections`, each with `id`, `owner_fingerprint` and
`launch_file`. Each launch file is the existing trusted bridge launch object
(`storePath`, `keyHex`, complete `binding`). It must already exist, be owned by
the current OS user, have mode 0600, and contain no symlink path component. The
store directory must have mode 0700. Nothing is enrolled or provisioned by HTTP.
The current launch file is re-read for each operation, so a host scope/key change
cannot be silently ignored by an old review. These are existing host credentials,
not an additional persistent credential generated by this feature. The launch
file contains the reused bridge key in plaintext protected by host filesystem
permissions; it is not an owner-vault or production key-management solution. A
backup containing both key file and database can decrypt the draft store.
Protecting that host secret remains the embedding host’s responsibility.

The fixed package-owned Node helper takes one bounded JSON request on private
stdin and returns one bounded JSON reply on stdout. There is no shell or new
listener. Commands, URLs, paths and credentials are not browser parameters.
The executable is the trusted installed Node 24 found by the host's PATH;
no caller-supplied executable is accepted. Child environment is allowlisted,
stderr is discarded, output is capped at 32 KiB and the caller has a five-second
deadline. It does not inherit provider credentials, shell options or telemetry.
The helper sees authorised plaintext. Same-user/root compromise is excluded.

## Exact dismissal and uncertainty

Reviews show the immutable request ID, title and instruction, host/session/
conversation/recipient/owner binding, original host lease and keyed digest.
A two-minute review token is bound to this content, binding, authenticated owner
session digest and session expiry. Dismissal rechecks the current scope,
revocation, host lease, durable observed-clock fence, review lease and owner
session deadline, including the final database commit gate. The Python wrapper
holds the actual owner's local revocation ordering through the helper and
re-authenticates after its return. No bearer session is passed to Node.

One encrypted dismissal receipt is durably saved per draft. An exact repeated
click returns the original decision; abandoned output must be reconciled by
inspection, never an automatic retry. Restart locks the owner's account; a new
login must obtain a new review, while the saved dismissal ID remains unchanged.
The MCP status can report `dismissed`, but always retains `ownerConsent:
not_requested`, `transportReceipt: none` and `execution: not_started`.

This queue requires the exact active host lease, bounded to **15 minutes** by
the bridge. Revoked or expired host scopes are unavailable through this owner
queue too, even if encrypted drafts remain on disk. It is not a general
persistent owner archive and never silently renews a lease. An unavailable
connection is displayed as unavailable, not an empty successfully inspected
inbox. Independent owner archival review is a separate future policy decision.
The old trusted `inspectForOwner` embedding API still preserves its archival
inspection semantics; it is not the authenticated HTTP API or a model tool.

## Storage upgrade requires an offline stop

New stores use schema version 2 and an additional authenticated encrypted
`owner_dismissals` table. Default constructors, the MCP launcher and the HTTP
helper **refuse v1 stores**. No automatic migration takes place.

A trusted embedding host may explicitly open `DraftStore(path, key, Date.now,
{allowOfflineV1Upgrade: true})` only after stopping **all** old bridge/store
processes, with a verified backup and the current key. The upgrade recognises
only the exact v1 schema and key marker, preserves existing scopes/drafts/time
fences, and installs the v2 schema atomically. Unknown schemas, wrong keys,
partial upgrades and unknown versions fail closed. Restart only the new code.

This is a cooperative operational requirement, not a process-exclusion lock:
an already-open v1 binary checks its schema at construction only and remains
able to use its old methods if an operator incorrectly upgrades underneath it.
The original PR20 implementation was directly exercised to confirm this limit.
An old process reopening the upgraded store refuses it. We do not claim that a
version marker retrospectively fences old live code. Concurrent mixed-version
operation is unsupported. Backup rollback and hostile same-user DB changes
remain outside the existing threat model.

## Verification scope

Disposable fixtures use the official OpenAI Agents Runner with deterministic
model output and real MCP stdio, then the actual authenticated owner HTTP routes.
No live provider/model call or real-person identity verification is implied.
Local Chromium cannot start in this executor; hosted browser acceptance is a
separate required gate. Final counts and exact-head evidence belong in the PR.

## Optional launcher

After independently provisioning the owner and supported host, launch the
existing workspace with `python -m workspace_ui.server serve --directory
/absolute/private/owner --host-draft-config /absolute/private/review-config.json`.
Do not put a key or password in argv. The extra flag is omitted by default.
The Host drafts view remains visibly disabled without it. The feature can be
removed by stopping the workspace and restarting without the flag; this does
not delete the encrypted draft or dismissal records.

The current published UI integration is the single-owner workspace. The facade
has a compatible authenticated-actor seam for the separate local conversation
coordinator, but that later composition requires its own publication and tests.
No unpublished conversation-controls code is part of this milestone.

The browser displays title/instruction via text nodes, exposes all fixed
bindings, and requires an unchecked exact-dismiss confirmation. Navigation,
visibility changes, session loss and review expiry discard selected plaintext.
Busy and uncertain outcomes prevent another write until inspection. No polling
or automatic owner action is scheduled.
