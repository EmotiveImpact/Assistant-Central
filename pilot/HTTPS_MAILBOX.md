# Optional HTTPS ciphertext mailbox

This is a transport building block, **not a deployed or production messaging
platform**. It adds no routes to the owner server, no peer login, no scheduling,
no provider permission and no decryption. Use only fictional owners and synthetic
packets in this pilot. The dependency remains `cryptography==50.0.0`; HTTPS uses
Python's standard TLS implementation. Linux private-file/flock semantics apply.

## Explicit owner flow

1. Independently compare and enroll the peer identity fingerprints, then review,
   release and export a packet using `pilot.file_exchange` (see FILE_EXCHANGE.md).
2. The recipient explicitly configures a separate private quarantine directory,
   recipient fingerprint, certificate and private key. `MailboxServer` is disabled
   unless `enabled=True` is supplied. Its default address is `127.0.0.1:0`; it does
   not listen remotely unless a caller explicitly overrides the address. No public
   deployment, persistent credentials or remote call is included here.
3. The sender explicitly calls `send_file(exported_file, chosen_https_url,
   expected_recipient_fingerprint, ca_file=optional_test_CA)` once. The only target
   path is `/v1/quarantine`. Hostnames and IPv4 are supported, not IPv6 URLs.
   There are no credentials, cookies, owner sessions, proxy settings or redirects.
   The explicit CA affects only that connection's context, never system trust.
4. The recipient owner chooses the digest-named private quarantine file and imports
   it with the existing authenticated file-exchange CLI. The mailbox does not
   inspect owner stores and cannot enroll senders, import packets or accept work.
5. Send the **original signed receipt file** back through the same file/HTTPS path
   and authenticate its import on the sender. No receipt is generated by HTTP.

The exported raw packet bytes are transmitted and stored unchanged. The filename
is their SHA-256 digest; the carrier also reports the existing canonical packet
digest and expected recipient fingerprint. Structural checks do not authenticate
an attacker-supplied signature. Only authenticated import verifies pinned peers,
cryptography, expiry and replay and applies the inert task state.

An exact fixed HTTP acknowledgement means only that the untrusted peer *claims*
quarantine. The carrier always returns `delivery: uncertain`,
`owner_acceptance: not_established` and `authorises_execution: false`, including
for a forged successful HTTP response. It never updates owner runtime state.
A cryptographic receipt means durable receipt only, not acceptance or execution.

## Local synthetic API example

First provision private mode-0600 disposable test certificate/key files in a
private directory; never pass secret contents in arguments or print them. No
certificate creation or server is run by importing these modules.

```python
from pilot.https_mailbox import Quarantine, MailboxServer

# Paths and fingerprint are explicit local configuration, not peer inputs.
q = Quarantine(private_spool, expected_recipient_fingerprint)
server = MailboxServer(q, private_certificate_path, private_key_path, enabled=True)
try:
    server.serve_forever()
finally:
    server.server_close()
    q.close()
```

## Bounds, failure and retention

TLS chain and hostname verification is mandatory, TLS 1.3 minimum. There is no
insecure switch. Server certificate/key input uses the same pinned private file
boundary as packet input, then private temporary copies for OpenSSL's filename
API. These are named transient private-key copies, removed on normal exit; an abrupt
process/host crash can leave the private temporary directory behind for operator
cleanup. No persistent credentials are intentionally generated. The server does not request client
certificates: any connected peer can submit structurally valid ciphertext to the
configured fingerprint, but gains no owner authority.

One synchronous request is processed at a time, with a three-second total TLS and
request-read deadline and a backlog of four. Headers are at most 2048 bytes; the
exact method, path, four header names, media type and positive Content-Length are
required. Duplicate headers/members, transfer encoding, chunking, owner auth,
malformed JSON and raw bodies over 32768 bytes fail closed. Connections are closed
after one request; trailing/pipelined input is never processed. Errors are fixed,
with no body reflection or request logging. The client accepts only a bounded
fixed acknowledgement and does not interpret peer JSON or follow redirects.
Each resolved-address connection attempt, TLS and send phase has a three-second
timeout; the bounded response has a three-second total read deadline. System DNS
resolution and filesystem I/O can still block and are not hard real-time bounded.
The system connector may try multiple resolved addresses before connecting. This
is not a hard overall client deadline; packet transmission is attempted once,
never retried on another connection. ACK/error sends recheck the server read
deadline after storage, but slow fsync can still hold the single worker.

The spool has an exclusive process lease and serialized capacity checks. Default
limits are 64 packet files and 1 MiB, configurable only locally to hard maxima of
1024 files and 32 MiB. It never evicts or overwrites. Full, partial and otherwise
invalid retained entries consume capacity or stop ingestion. Unsafe directory
permissions, symlinks, multiply-linked files and insecure file modes are refused.
Writes use exclusive mode-0600 creation and file/directory fsync before ACK.
Exact duplicates are acknowledged only after checking the existing raw bytes and
resyncing them; a partial file is never silently repaired or replaced.

Interrupted writes, fsync, connections and acknowledgement loss can leave partial
or complete files. The sender may not know which. **No automatic retry, cleanup,
renewal, resealing or eviction occurs.** Inspect owner outbox and retained files
before any explicit next step. Sending an already-exported file again does not
call `prepare_delivery` again: export recorded one uncertain owner delivery attempt;
this separate transport cannot enforce an aggregate send count or recall a copied
file. Expired/revoked packets may occupy quarantine, but authenticated import still
rejects them. Owners must manage retention and securely provision certificates.

This small single-worker server is deliberately susceptible to queue exhaustion
and spool-filling denial of service. It is not Internet-hardened. TLS proves the
selected hostname under the selected CA, not the owner's peer fingerprint. A
mailbox/admin can retain ciphertext, lie about storage or expose metadata. Root or
malicious processes with the same OS account can compromise memory, files and
locks; these are outside the private-file threat boundary. No public endpoint,
cross-device identity validation, deployment rate limiting, certificate lifecycle,
backup/retention policy or production security review has been delivered.

## Verification

```sh
python -B -m unittest pilot.tests.test_https_carrier -v
python -B -m unittest discover -s pilot/tests -v
```

Tests create disposable fictional CA/server keys in temporary private directories,
run actual ephemeral TLS servers on loopback, then remove test inputs. They cover
trusted TLS, bad CA/hostname/expiry, TLS downgrade and plaintext rejection,
framing/JSON bounds, immutable duplicate storage, capacity, concurrency, unsafe
files, interrupted storage and acknowledgement uncertainty, no silent retry and
original authenticated file receipt import without acceptance.
